How these numbers are built. Every assistant turn in the Claude Code transcripts is read, deduplicated on message id (forks and resumes copy turns into new files), then priced at published API rates per model and token kind. Calibration turns "share of my usage" into "share of that limit." With live readings connected, each dial starts from the percentage Anthropic reports and adds only what you've spent since that fetch — so it can be behind by at most one refresh. Without them, the whole percentage is inferred from a scale worked out the last time a reading was seen, which drifts: the real meter counts every surface on your account, and these transcripts only cover Claude Code on this machine. Percentages are estimates; the ring colors track burn rate against the window's remaining time, not raw fill.

Live readings optional
On, Token Ledger asks Anthropic for your usage percentages on every refresh, so the dials show the same numbers as the Usage tab instead of estimating between /usage runs. This is the most accurate mode, and it costs no tokens — it reads the meter, it doesn't talk to a model.
read Claude Code's login and fetch my percentages
Off
Token Ledger reads the login Claude Code already stores on this machine — the Keychain on macOS, %USERPROFILE%\.claude\.credentials.json on Windows, ~/.claude/.credentials.json on Linux — and sends it to Anthropic's usage endpoint, nowhere else. It is read only: never copied, never written back, and never refreshed, because renewing that login is Claude Code's job and rotating it could sign you out of your terminal. macOS asks your permission the first time. Leave this off and nothing breaks — Token Ledger falls back to Claude Code's cached reading, or to percentages you type in below.
